# 第五阶段：活动价前台可见、AI 配置可保存、AI 工具真正可用

## 1. 活动不自动减免价格（前台看不到活动价）

**后端计价本来就是对的**，问题在前台拿不到活动价：

- 商品列表与商品详情接口只返回原价，买家只有在付款页才第一次看到减免，
  所以在店铺里「活动看起来没生效」。
- 更深一层的原因：我最初接给商品接口的计价调用**没有传单价**。
  活动规则是按「单价 × 数量」计算的，缺了单价一律算出 0，于是永远判为「无活动」。

修复：

- 新增 `ActivityPricer` 端口，由容器注入商品模块（模块之间不互相 import）。
- 商品列表与详情返回 `activity_price` / `activity_name` / `activity_saving`。
- 这两个路由改为可选登录，已登录买家拿到的是按自己账号计算的活动价。
- 前台商品卡片与详情页显示活动价、划线原价、活动名与「已省多少」。

实测：原价 100 的活动商品，列表与详情都返回 `activity_price=90`、
`activity_name=全场9折`、`activity_saving=10`。

### 关于「每人限次」
活动默认每人限次 1 次，所以同一个账号第二次下单不再减免——这是设计行为。
需要重复享受的活动把「每人参与次数」设为 0（不限）。

## 2. AI 客服配置保存不了

根因：`AIConfig.APIKeyEnc` 的 JSON 标签是 `json:"-"`
（防止密钥出现在任何响应里），但保存处理器直接用它绑定请求体，
于是前端提交的 `api_key` **被静默丢弃**——密钥永远存不进去，
启用时又报「请先配置 API Key」，看起来就是保存无效。

修复：新增 `aiConfigRequest` 显式接收 `api_key`，
写入时再赋给 `APIKeyEnc`。留空保持原值、`__clear__` 清除。

实测：带密钥保存返回 200，`has_key=true`，响应里不含密钥原文。

## 3. AI 现在真的能调用工具

之前的问题：**系统提示词里根本没有告诉 AI 有哪些工具**，
所以模型只会凭知识库回答，或者直接建议转人工，工具形同虚设。

新增三块能力：

### 工具清单写进提示词
`enabledToolCatalogue` 把「已启用 且 当前角色可用」的工具列进系统提示词，
并给出调用格式：`{"tool":"工具标识","params":{...}}`。
提示词里有什么，AI 才可能调用什么；执行时 `CallTool` 还会再校验一次权限，
所以写进提示词不会扩大权限。

### 工具调用循环
`runToolLoop` 实现「模型 → 工具 → 模型」的循环（最多 3 轮）：
模型输出工具调用 → 系统执行 → 结果回喂 → 模型给出最终回答。
工具失败也回喂给模型，让它能向用户解释，而不是整段对话失败。
每次调用都写 `ai_tool_calls`，参数与结果脱敏。

### AI 可调用的工具（18 个）
| 分类 | 工具 |
| --- | --- |
| 账号 | `user.profile` |
| 订单 | `order.list`、`order.detail`、`order.payment_status`、`order.delivery_status` |
| 商品 | `product.detail`、`product.list` |
| 活动 | `activity.list` |
| 知识库 | `knowledge.search` |
| 工单 | `ticket.list`、`ticket.create`、`ticket.transfer`、`ticket.add_message`、`ticket.update_status` |
| 退款 | `refund.list`、`refund.order` |
| 通知 | `notification.send` |
| 优惠券 | `coupon.grant` |

安全边界：全部限制在调用者自己的数据（`own_data_only`）；
高风险工具（更新工单状态、发通知、退款、发券）默认需要确认或默认停用；
参数走白名单与类型校验；有独立超时与限频。

后台新增「AI 可调用的工具」面板，按角色查看 AI 实际收到的工具清单，
与写进提示词的内容同源，店家可以在这里核对。
